# Roadmap

The roadmap is organized around proof, not feature volume. Each phase has an exit condition.

## Phase 0 — Product lock

**Goal:** Resolve the decisions that materially alter the experience.

- Choose the first user and first-use context
- Choose the primary device and interaction posture
- Define the one-palace content model
- Define success measures for capture, placement, and recall
- Establish the privacy and AI boundaries

**Exit condition:** A concise product design is approved without unresolved structural choices.

## Phase 1 — Visual and spatial exploration

**Goal:** Find the visual language that can carry clarity and enchantment together.

- Produce three distinct directions using the same canonical screens
- Show atlas, house, room, memory detail, and recall states
- Define typography, cartographic grammar, color, material, iconography, and motion
- Test dense, empty, strong-memory, fading-memory, and reduced-motion states

**Exit condition:** One visual direction is selected and its design laws are explicit.

## Phase 2 — Interactive experience prototype

**Goal:** Prove the complete experience before selecting the production architecture.

- Navigate atlas → house → room → locus
- Add and encode a memory
- Place or move it
- Complete a recall walk
- See strength change after recall
- Inspect the map-like place page and retrieval history

**Exit condition:** The core loop is understandable, emotionally resonant, and testable without explanation.

## Phase 3 — Functional personal alpha

**Goal:** Make one palace useful across repeated days.

- Durable local or private cloud persistence
- Fifteen working loci across three rooms
- Recall scheduling and confidence capture
- Synthetic demonstration content plus private user data outside the public repository
- Export, backup, and recovery
- Keyboard, touch, accessibility, and reduced-motion support

**Exit condition:** A user can rely on one palace for several weeks without data loss or navigation confusion.

## Phase 4 — Recall validation

**Goal:** Determine whether the experience improves durable retrieval.

- Measure free-recall success rather than simple recognition
- Track response confidence separately from correctness
- Diagnose weak cue, sequence, name, image, and interference failures
- Compare suggested schedules with actual performance
- Refine mnemonic coaching without increasing friction

**Exit condition:** Recall behavior informs the product rather than serving as decorative statistics.

## Phase 5 — Atlas expansion

Expand only after the one-palace loop succeeds:

1. Multiple palaces and territory overview
2. Life Chronicle
3. People Palaces
4. Recitation mode
5. Cross-memory connections
6. Inkbound capture integration
7. Optional Wayward Atlas experiments

## Quality gates across every phase

- No personal memory content enters the public repository
- No animation exists without communicative purpose
- No feature bypasses genuine retrieval
- No design direction is selected without representative screens and states
- No expansion begins while the core loop remains unclear or unused
