# Working Vision

This document captures the current product hypothesis. It is not yet a locked implementation specification.

## Product statement

Mischief Atlas is a spatial operating system for remembering a life: a navigable atlas in which familiar places become durable homes for knowledge, passages, people, experiences, and life chapters.

Its purpose is not to store more information. Its purpose is to keep meaningful information retrievable.

## Human problem

Digital archives preserve records while allowing lived experience to become psychologically distant. Notes, photographs, highlights, and contacts accumulate, but most are rarely retrieved without an external cue.

Mischief Atlas turns passive archives into active memory practice by binding information to familiar spatial structures and returning it through deliberate retrieval.

## Product promise

The user should be able to:

1. Capture something worth retaining.
2. Convert it into a vivid, personally meaningful cue.
3. Place it within a familiar spatial locus.
4. Revisit that locus through a guided recall walk.
5. Strengthen the memory through scheduled retrieval.
6. understand which part of recall failed and improve the encoding.

## The spatial model

**Atlas → Territory or Palace → Room or Zone → Locus → Memory**

A memory carries:

- Content and source
- Spatial address
- Mnemonic image or association
- Retrieval path
- Importance and emotional weight
- Recall history
- Current strength and confidence
- Connections to people, periods, places, and related memories

## Experience laws

### The map must orient

At every depth, the user should know where they are, where they came from, what lives nearby, and how to return.

### Memory state must be visible

Visual intensity reflects recall condition: stable memories appear richly resolved; uncertain ones soften; neglected ones fade without becoming irrecoverable.

### Magic must carry information

Footsteps, drawing ink, unfolding rooms, revealed doors, and margin annotations are useful only when they clarify paths, states, or consequences.

### Recall comes before revelation

During practice, answers remain hidden long enough for genuine retrieval. Recognition is not treated as recall.

### AI proposes; the user authors

The system may suggest mnemonic images, loci, relationships, or schedules. The user approves the association because personally generated meaning is part of the encoding.

### The archive remains humane

People are represented through shared texture and meaningful recollection, not scored as contacts or managed as sales leads.

## First experience candidate

A user opens one familiar house, enters a room, selects a locus, places one meaningful memory, and later completes a short recall walk. The house changes subtly as the memory strengthens.

## Explicit non-goals for the first build

- A global real-world GIS platform
- Social feeds or public memory sharing
- Points, leaderboards, streak pressure, or decorative reward economies
- Complete support for every mnemonic technique
- Inkbound or BOOX handwriting integration
- A general-purpose notes database
- Multi-palace scale before the first palace feels excellent

## Open product decisions

- Is the first release a personal working atlas, public alpha, or cinematic proof?
- Is the primary surface desktop-first, tablet-first, or deliberately balanced?
- Should the initial atlas be geographic, schematic, or a hybrid?
- Should the house be represented as a floor plan, architectural cutaway, illustrated diorama, or layered combination?
- Which recall outcomes define success during the first month of use?
